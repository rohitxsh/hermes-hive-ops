1. Read the card first: `hermes kanban show <id>` (latest comments, events and runs) and `hermes kanban diagnostics --task <id>`.
2. Leave it alone, with no comment, when it is waiting on a person (except the daily waiting-on-person re-check in step 3): an approval, review, sign-off, answer or decision; a human-only step (an account, password, CAPTCHA, payment); a hold set by the owner or a person (check the comments); or the quota pause (`quota-status --gate` says paused, or the card is only waiting because every provider is used up). The PM's evening summary covers those.
3. Otherwise fix the cause and move the card on:
 - blocked on a gap you can close as admin (a card link to add or remove, a wrong completion contract, a missing directory or tool, a bug in our own scripts under ~/agents/src, a session pinned to a dead provider): fix it, then `hermes kanban unblock <id> --reason "<what you fixed>"`.
 - blocked on a transient error (a GitHub or provider outage, a network error) that has cleared, or a quota pause has ended (`quota-status --gate` no longer says paused): unblock it with that reason.
 - waiting-on-person Nd (listed once a day): re-read the card's question, its latest comments and the conversation it names. Release it to its owner (`kanban-doctor release <id> "<why>" --to <profile>`) when the answer is already there (quote who said what, and when), when a newer rule in the SOUL or its Shared rules block makes the question unnecessary (name the rule), when it only asks people to confirm receipt or that a file opens, or when another card superseded it. Otherwise leave it: it really waits on a person and the evening summary lists it.
 - held in triage after a block loop for a reason that isn't a person: fix the cause, then `kanban-doctor release <id> "<what you fixed>" --to <owner>`.
 - unassigned (the line shows who created it): assign it to that profile with `hermes kanban assign <id> <profile>`, unless the card names another owner.
 - ready or in review but not picked up: find what holds it back in `hermes kanban diagnostics --task <id>` (cooldown, auth, a PR URL in the assignee's own comment) and fix that cause.
 - running with no heartbeat: `hermes kanban reclaim <id> --reason "<why>"`.
 - handing a card from review back to its implementer (QA findings to fix): `hermes kanban reopen-review <id> --reason "<why>"`, then `hermes kanban assign <id> <implementer>`. `kanban-doctor release` returns a card to the lane it came from, and an implementer started from the review lane gets a review-only run that can't change code.
 - todo although every parent is done: `hermes kanban promote <id>`.
 - parked for over a day: check what it waits for; if that already happened (the PR merged or was approved, QA passed), unblock it; if it waits on a person, leave it.
 - repeated crashes: read `hermes kanban log <id>` and the last run's output and fix the cause. If the work is in fact done and you verified it, `hermes kanban complete <id> --result "<evidence>"`.
