Weekly skill review (no change to any skill without the owner's OK). The monitor output above ranks our own skills that show trouble: agents re-reading them in the same session, and sessions that used them and then hit the loop guard. It also lists own skills nobody used.
1. Run `quota-status --gate`; if it says paused or wrap up, reply exactly [SILENT]. If no skill has a score of 10 or more and nothing is unused, reply exactly [SILENT].
2. Take the ONE highest-scoring skill. Find every copy: `find ~/.hermes ~/agents/shared-skills* -path '*/<name>/SKILL.md'`. Read it, and look at how agents used it (session_search for the skill name; the efficiency command's skill section). Work out why agents re-read it or got stuck: too long, key steps buried, conflicting instructions, missing a command they then guessed.
3. Write ~/agents/skill-proposals/YYYY-MM-DD-<name>.md with: the problem in two lines; the evidence (the numbers above, two or three concrete examples); the proposed change as a unified diff of SKILL.md (shorter and clearer, the steps agents keep needing first, rarely used detail moved to references/); the expected effect; and a "How to apply" section: back up every copy (SKILL.md.bak-<date>-review), apply the diff to every copy, log it in ~/agents/ADMIN-CHANGES.md, confirm in one line.
4. Do not edit any skill. For unused skills, add one line to the proposal suggesting whether to keep or retire each.
5. Reply in at most six lines: the skill, the problem, the proposal path, and: reply "apply skill proposal <file name>" to apply it.
